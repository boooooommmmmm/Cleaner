## 1. 产品定位

面向 Windows 个人用户与开发者，识别缓存、卸载残留和磁盘占用，提供明确的清理依据、风险说明与恢复入口。

普通文件清理优先使用隔离区。回收站清空、文件粉碎、永久删除和部分系统命令具有不同的恢复边界，界面必须明确说明。

范围约束：不做文件恢复、软件搬家、桌面整理、进程注入或全局钩子；不把注册表清理或工作集清理宣传为系统提速。

## 3. 清理类模块

### 3.1 系统垃圾清理

由签名规则库定义范围。先统计并展示结果，再按当前可见且勾选的条目执行。占用文件跳过并保留明细；扫描后变化、白名单与权限限制需要执行前再次核对。系统命令使用固定操作表。

### 3.2 浏览器与应用缓存

支持规则指定的应用及多配置目录。清理缓存、配置和登录态的后果必须区分，具体覆盖以 `rules/` 中通过签名与路径校验的规则为准。

### 3.3 用户目录残留

结合软件清单、应用指纹、卸载记录及目录信息识别残留。清单不可靠或无法确认归属时保留不确定性，不能把“没读到”直接当成“已卸载”。

凭据、用户 hive、系统路径、重解析点与白名单由引擎保护。Documents、游戏存档等个人内容不默认勾选。多用户扫描遵循当前权限；服务根据已认证的连接方身份解析用户路径。

工作区新增独立的[僵尸目录入口](可清理范围与僵尸目录-2026-10-02.md)：只展示有卸载记录的明确缓存、日志及真正为空的目录，限定当前用户 AppData，默认建议确认。非空应用根目录和个人文档不进入该清单，执行前重新核对安装状态与文件范围。该首版尚未发布。

### 3.4 注册表与失效配置

无效卸载项、快捷方式、MUI 缓存、遗留软件键、关联、App Paths、服务、任务及高级注册项按相应扫描器判定。删除经过护栏并先备份，执行前重新比对内容快照及缺失路径依据。备份失败不能继续删除。

注册表导入与计划任务重新注册有各自的合并、冲突及权限限制，不保证完整撤销所有后续变化。

### 3.5 空间分析与重复文件

空间分析枚举目录，展示 TreeMap、目录占比及最大文件，跳过重解析点和云端占位文件。重复查找按大小、首尾哈希、全量哈希确认并排除硬链接。支持整行及 Ctrl / Shift 多选；每组至少保留一份，执行前复验保留副本。

磁盘历史快照、跨次对比、直接读取 MFT 尚未作为当前实现提供。

### 3.6 隐私与粉碎

历史记录按现有扫描器与备份机制清理。文件粉碎、机械盘空闲空间擦除属于不可恢复操作；SSD 上覆写不作彻底擦除保证。危险操作需明确确认及适用范围限制。

## 4. 优化与状态工具

- 启动项展示签名、路径、建议与系统可提供的影响数据；无记录时显示“未测量”。微软服务与任务默认隐藏，可单独显示。
- 磁盘操作调用 Windows 固定命令，需要管理员权限；固态盘禁止碎片整理。
- 内存工具保护关键进程，不提供工作集清理。
- 服务优化记录原始启动类型，恢复只针对本程序修改过的服务。
- 硬件状态使用现有公开接口，不安装内核驱动。传感器、权限或厂商工具不支持时明确显示不可用。

## 5. 管理工具

- 卸载调用官方卸载程序；程序缺失时可备份后移除登记项。
- 安装监控提供前后快照差异，当前不提供完整安装回滚。
- 驱动页提供导出与旧包识别等操作；导出包不等于自动恢复已经验证。
- 弹窗拦截使用窗口枚举和规则内 IFEO 操作，默认关闭。
- 修复工具执行固定系统命令及已有备份操作。

## 6. 安全与体验约束

### 6.1 用户可见的机制

1. 先扫描后清理，展示依据、影响、恢复方式和前置条件。
2. Safe 默认勾选；Confirm 与 High 默认不勾选；NotRecommended 仅高级模式可见。保存的选择按用户、条目、类型与风险匹配。
3. 普通文件进入同卷隔离区。默认保留 30 天，每卷上限取卷容量 10% 与 20 GiB 较小值；超限可能提前淘汰。永久删除后不再可恢复。
4. 注册表写入使用键级或值级备份，恢复前验证范围与完整性。
5. 修改服务启动类型前按设置尝试系统还原点，失败时明确提示。
6. 白名单约束扫描与执行范围；筛选外仍勾选的条目不参与当前清理。
7. 定期扫描、自动清理尚未实现；候选范围见开发计划。
8. 操作日志记录批次与逐项结果，可导出并识别未正常结束的批次；识别不等于自动恢复已完成。

### 6.2 引擎约束

1. 不跟随重解析点；移动与恢复使用句柄核对真实位置。
2. 拒绝保护路径及不允许的范围；系统回收站只通过 Shell API 操作。
3. 规则路径使用允许的环境变量，禁止目录跳转与保护路径，拒绝不合法规则。
4. 数据集与更新包验证可信签名和哈希，同时检查路径、版本及执行范围；更新来源使用 HTTPS。
5. 固态盘禁止碎片整理。
6. 文件、目录、注册表等对象执行前重新核对扫描依据，变化时拒绝或跳过。

索引、sidecar 与备份验证一致性和范围；同账户进程一致篡改全部材料不在现有独立信任保证内。系统命令只使用固定程序和参数表；提权协议采用枚举型操作，服务自行解析路径并重扫。

## 7. 技术架构

### 7.1 技术选型

.NET 10、WPF、CommunityToolkit.Mvvm、SQLite。当前发布包为 win-x64 自包含产物；发布脚本支持指定 RID，其他架构的验收状态单独记录。

### 7.2 公共服务

ScanScheduler 汇总扫描结果；CleanEngine 执行清理；Quarantine、RegistryBackup、OperationLog 维护隔离、备份及批次记录。AppServices 组合服务，ViewModel 管理界面任务与状态。

### 7.3 规则格式与语义

模型见 [CleanRule.cs](../src/CleanSweep.Core/Rules/CleanRule.cs)，实际数据见 [rules/](../rules)。

- 规则含 id、应用信息、detect 与 targets；目标含 path、kind、risk、when、说明及可选匹配条件。
- when 为 installed、uninstalled 或 always；应用清单的不确定性由相应扫描器保守处理。
- kind 支持文件集合、目录、命令和回收站；命令与回收站有独立执行及恢复语义。
- path 使用允许的环境变量和路径，不含目录跳转；模板与展开路径分别校验。
- 目录段通配只枚举直接子目录、跳过重解析点、最多 200 个；不可在变量段、最后一段或紧随环境变量处使用通配。
- exclude 仅适用于 files 的文件名匹配，不接受路径分隔符或排除全部的星号。
- 修改规则、指纹或弹窗数据后重新签名，加载器只接受签名清单内哈希匹配的文件。

### 7.4 权限与更新

界面以普通权限启动。提权服务验证连接方身份及程序，按连接方 SID 解析用户目录。未签名构建的客户端签名检查状态见[当前状态](当前状态.md)，不能仅凭存在校验代码声称已启用代码签名保护。

程序更新先后台下载并校验，用户同意后安装。启动时可恢复已校验完整包，页面忙碌或规则更新时暂缓安装。安装目录中的已有程序再次验签后执行暂存与事务式替换；失败处理需结合真实权限环境验收。

## 9. 验证策略

统一入口 tools/verify.ps1 覆盖构建、Core / App 测试、版本一致性及公开签名，可附加目录与 ZIP 验证。界面回归可加载实际 WPF 页面，清理测试使用受控临时对象。

性能优化先建立可重复基线，再报告首批结果耗时、总耗时、内存和取消响应。早期设计中的耗时、误报率或百分之百恢复目标不作为已经测得的结果。

当前测试数量、CI、公开包证据和真实环境未验证项见[当前状态](当前状态.md)。
