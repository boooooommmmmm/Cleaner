## 使用流程

1. 启用启动检查后，发现新版本会在后台下载，并校验下载内容。
2. 设置页显示下载百分比和已下载大小，可点击“取消程序更新”；取消或失败后，可点击“检查 / 重试更新”。取消仅作用于程序更新，不取消独立的规则库更新。
3. 下载完成后询问是否安装。选择稍后会保留安装入口，并可在设置页展开查看版本说明。
4. 重启时先读取本地缓存索引。来源一致、签名可信、版本高于当前且包大小与哈希一致时，恢复“安装已下载更新”。此恢复步骤无需联网，也不会主动弹出安装确认；关闭启动检查仍会执行本地恢复。
5. 启用启动检查时，本地恢复后继续正常联网检查；网络失败会保留已准备好的包。检查尚在进行时，可取消程序更新操作，再使用已下载包的安装入口。
6. 清理、扫描、粉碎、隔离区操作等导航页任务或规则库更新正在运行时，保留已下载包并提示暂缓安装。结束任务后，在设置页手动安装。

## 实现要点

### 下载状态和取消

- `AppUpdateCoordinator` 统一维护检查、下载、恢复和安装准备阶段的忙碌状态与取消令牌。
- 百分比限制在 0–100；已结束、已取消或旧更新来源的进度回调不会覆盖状态。
- 取消后不弹安装确认、不启动安装器，并恢复检查入口。
- 切换更新来源会清空当前待安装状态；旧异步任务完成或失败时不能覆盖新来源状态。

### 本地缓存恢复

- `PreparedAppUpdateStore` 在下载目录写入 `prepared-update.json`，只保存来源与资产文件名，以临时文件替换方式更新索引。
- 读取索引时限制为普通 ZIP 文件名，拒绝绝对路径和目录跳转。
- 索引不能作为信任依据：每次恢复都重新验证旁边的发布信息签名，以及包版本、文件名、大小和 SHA-256。
- 文件损坏、签名无效、密钥不可信、来源改变、版本已安装或更旧时，都不会恢复安装入口。
- 安装前还会再次验证包；实际替换仍使用安装目录内已有程序执行原有校验和事务式替换流程。

### 安装与任务协调

- `UpdateInstallGuard` 遍历全部导航项的任务状态，包含未选中的页面，防止切换到设置页后漏掉仍在运行的清理任务。
- 弹出安装确认前，以及用户同意后启动安装器前，都会检查任务状态。
- 规则库更新用同一信号量串行执行；有规则库更新进行时，程序安装也会暂缓。
- 暂缓后保留安装包，任务结束后由用户手动安装。

## 边界与后续实机验收

- 本轮提供显式重试和完整包复用；未实现按 HTTP Range 从中断位置继续下载。
- 重启恢复依赖本轮新增的缓存索引。旧版本留下但没有索引的包，需要检查更新后通过原有缓存校验流程复用。
- 安装阻止条件覆盖导航页明确报告的忙碌任务以及规则库更新，不是整个操作系统或所有后台服务的任务锁。
- 自动化测试使用临时文件、测试签名密钥和模拟安装回调，不会实际安装更新或执行清理。
- 真实 UAC、管理员 / SYSTEM 服务更新与安装回滚仍需在对应环境做端到端验收；本轮未触发实际替换，也未发布新版本。
