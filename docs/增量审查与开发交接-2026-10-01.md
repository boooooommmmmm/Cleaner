## 发现与修复

### O01 · P1：清理页隐藏的已选项目仍会执行

**原行为：** 结果筛选只改变 IsVisible，CleanAsync 仍从全部 Items 取 IsSelected。用户筛选 Chrome 后，隐藏的 Edge 等默认选中项也进入清理请求；组复选框和“只选安全项”也作用于隐藏项。

**修复：** 新增 SelectedVisibleItems，清理、计数和体积共用这一集合。组复选框与批量选择只作用于显示项，隐藏项保留选择但本次不处理；确认框、按钮和汇总明确说明范围。过滤后移除最后一个显示项会隐藏空组，扫描期间输入的过滤条件也应用于新结果。

**位置：** [ScanItemViewModel.cs](../src/CleanSweep.App/ViewModels/ScanItemViewModel.cs)、[CleanPageViewModel.cs](../src/CleanSweep.App/ViewModels/CleanPageViewModel.cs)、[CleanPage.xaml](../src/CleanSweep.App/Views/CleanPage.xaml)。

**验证：** 4 个 App 测试覆盖隐藏选择、组复选框、权限禁用项、过滤通知和 CleanCommand 可执行状态。测试没有点击真实清理确认框或删除用户文件。

### O02 · P1：隔离区“删除过期项”忽略当前筛选范围

**原行为：** 新版“全部恢复/清空隔离区”使用当前 Rows，但“删除过期项”仍调用全索引 PurgeExpired。选择磁盘/批次后，操作可能删除其他筛选外的过期项；该分支也没有使用已有的服务回退流程。

**修复：** 在点击时固定当前 Rows 中已过期的条目，确认框明确范围，使用统一 RunBulkAsync 和逐项权限回退。失败不会被无声归结为“没有过期项”。

**位置：** [QuarantineViewModel.cs](../src/CleanSweep.App/ViewModels/QuarantineViewModel.cs)，PurgeExpiredAsync。

**验证边界：** 静态追踪执行集合、构建通过；未在真实隔离区执行永久删除，完整 WPF 点击/服务回退仍需 VM 验收。

### O03 · P2：健康的内存诊断被标红

**原行为：** 使用 `diag.Contains("错误")` 判断警告。“未检测到错误”同样包含“错误”，正常结果也会警告。

**修复：** 将诊断结果改为文字 + HasErrors，按事件结果确定状态；未知事件保持未知，不判为正常。

**位置：** [HardwareStatus.cs](../src/CleanSweep.Core/SysInfo/HardwareStatus.cs)。

**验证：** 1201 正常、1202 错误、未知事件三个回归。使用模拟事件结果，不制造真实内存故障。

### O04 · P2：目标风扇转速被当成实际转速

**原行为：** 读取 Win32_Fan.DesiredSpeed 后直接显示 RPM，用户会将其理解为实际测量。

**修复：** 明确显示“目标转速（非实测）”；没有值时显示实际转速未提供。

**依据：** [微软 Win32_Fan 文档](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-fan) 将 DesiredSpeed 定义为请求的目标转速，实际转速需关联传感器。此项是字段语义修正，未增加驱动或硬件控制。

### O05 · P2：发布检查忽略未跟踪源码

**原行为：** release.ps1 使用 `--untracked-files=no`，并注释称未跟踪文件不进构建产物。SDK 项目可能按默认文件匹配编译未跟踪的 .cs，发布包就不对应声称的提交。

**修复：** 发布前后调用 verify-release-source.ps1，检查已跟踪改动和未跟踪文件，仅允许生成的 release/latest.json。构建前后 HEAD 必须一致，检查在读取发布凭据前完成。

**验证：** 临时 Git 仓库中的集成测试确认干净状态通过、生成元数据允许、未跟踪源码与暂存改动拒绝。没有修改真实仓库配置或调用 GitHub API。

**边界：** 这不是完全隔离、可复现构建的证明。发布仍应使用受控工作目录；未来可升级为从指定提交创建独立构建目录，并验证工具链与依赖锁定。

### O06 · P2：发布版本可与实际程序版本不一致

**原行为：** -Version 可以任意指定，随后用该版本给 ZIP 命名、签名并创建 Release，未与发布程序的版本比较。可能反复提示升级或把旧二进制发布为更高版本。

**修复：** 打包前要求 -Version 与发布程序 ProductVersion 一致；新验证入口同时检查 App/Service 项目版本及应用清单版本。签名后再核对本地资产名称、大小与哈希。

**位置：** [release.ps1](../tools/release.ps1)、[verify.ps1](../tools/verify.ps1)、[ReleaseManifest.cs](../src/CleanSweep.Core/Integrity/ReleaseManifest.cs)。

**验证：** 已签名测试资产的正确内容通过，改名、等长篡改、改变长度分别拒绝；现有发布 ZIP 校验通过。没有运行正式签名或发布流程。

### O07 · P2：恢复说明遗漏容量淘汰，安全级别被解释为过强保证

**原行为：** 新详情写“保留 N 天，期间可恢复”，但 Quarantine.EnforceSizeLimit 可以提前淘汰。Safe 的通用文字还把残留配置/日志也描述成都会自动再生，注册表值恢复描述成备份整个键。

**修复：** 详情、清理确认和隔离区说明统一注明到期/容量淘汰条件；区分缓存再生与配置/日志恢复，注册表值说明与实际值级备份一致。

**验证：** 与现有淘汰、备份实现对照，相关说明测试继续通过。没有改变保留期或自动淘汰策略。

### O08 · P2：提权服务丢失占用文件的真实原因

**原行为：** 新增 InUseFiles 后，本地页面能显示“正在使用”；服务结果仍只查 Failures，因占用跳过被错误描述成“已变化或在白名单中”。

**修复：** 服务构造逐项结果时保留 InUseFiles 的原因，客户端已有结果显示流程即可显示正确说明。

**位置：** [ElevatedOperations.cs](../src/CleanSweep.Core/Elevation/ElevatedOperations.cs)。

**验证：** 用临时缓存规则和独占文件句柄调用实际服务操作实现，确认结果 skipped、说明含占用原因、源文件保留、隔离区无新增项。没有安装真实 SYSTEM 服务。

### O09 · P2：单项恢复/删除期间未设置共享忙状态

**原行为：** 批量操作会设置 IsBusy，单项恢复/删除等待服务时没有设置。虽然同一个异步命令通常拒绝重复执行，其他恢复/删除命令仍可能同时进入，导致同一隔离项状态交叉变化。

**修复：** 单项操作在执行前设置 IsBusy，并在 finally 恢复，统一禁用其他修改命令。

**验证边界：** 静态检查 RelayCommand 的 CanExecute 绑定及异常出口、构建通过；未制造真实 IPC 并发竞态。本轮不将其描述成已复现的数据丢失。
