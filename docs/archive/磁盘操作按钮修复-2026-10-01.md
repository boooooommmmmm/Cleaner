# 磁盘健康页按钮无响应修复

> 历史归档：正文描述记录当时的设计、代码与验证结果，其中的待办、版本和“未修复”不代表当前状态。请从[文档索引](../README.md)查看当前状态与开发计划。

## 原因与影响

磁盘页使用 `MultiBinding.StringFormat` 生成 `Button.CommandParameter`。该目标属性是 object 类型，实际页面中参数为 null，`DiskViewModel.RunAsync` 收到后直接返回。点击时既不会出现权限/操作确认框，也不会启动命令。

同一写法影响分析、优化、重新修剪、碎片整理和计划检查磁盘五个按钮。之前的权限检查发生在参数解析之后，因此无法解决这次问题。

## 修复

- [DiskViewModel.cs](../../src/CleanSweep.App/ViewModels/DiskViewModel.cs)：卷模型直接提供五种命令参数，非法参数和已消失的卷显示明确状态。
- [DiskPage.xaml](../../src/CleanSweep.App/Views/DiskPage.xaml)：按钮直接绑定对应参数属性。
- [DiskPageBindingTests.cs](../../tests/CleanSweep.App.Tests/DiskPageBindingTests.cs)：加载真实编译页面和资源，在 STA 线程检查两块测试卷的十个按钮，并调用点击处理验证参数传递；四个额外用例覆盖缺失、错误及过期参数。

管理员权限确认、操作确认及 SSD 禁止传统碎片整理的引擎约束继续生效。

## 验证

修复前页面回归失败：预期 `D:|Analyze`，实际为 null。修复后 Debug 界面测试 9 个通过；Release 完整验证为核心 450 个、界面 9 个通过，构建 0 警告、0 错误，数据集及发布元数据签名验证通过。

完整验证首次运行中，已有在线更新测试在创建本地 HTTP 监听器时遇到地址占用（测试使用随机端口）；再次完整运行通过。此测试基础设施问题未混入本次产品修复。

验证命令：

```powershell
./tools/verify.ps1 -Configuration Release -ResultsDirectory artifacts/verification/disk-button-fix
```

结果位于 `artifacts/verification/disk-button-fix`。测试使用捕获参数的命令，不会启动真实碎片整理或触发 UAC。修复已构建到源码目录下的 Debug/Release 输出，现有 publish 目录和发布 ZIP 未更新。
