# 可清理范围与僵尸目录

> 发布状态：本文功能已随 [v0.21.0](releases/发布验收-v0.21.0.md) 发布。以下开发记录中的“未发布”及测试数量描述实现当时的状态。

更新日期：2026-10-02。基于当前工作区，新增功能尚未发布；已发布版本仍为 v0.20.0。

## 1. 当前还能清理什么

| 类别 | 当前入口与覆盖 | 边界与后续方向 |
| --- | --- | --- |
| 临时文件、日志、崩溃转储、系统更新缓存 | 系统垃圾清理已有规则 | 继续补充具体软件的可再生成文件，保留文件年龄、占用及权限检查 |
| 浏览器与桌面应用缓存 | 应用缓存已有签名规则 | 补充具体版本路径及多配置目录；Cookies、登录数据库、书签、聊天记录不应按缓存扩大范围 |
| 开发工具下载缓存与构建依赖 | 开发者缓存已有实现 | 后续可增加用户指定项目的构建输出预览；源码、虚拟环境与数据库不能凭目录名认定可删 |
| 卸载后的缓存、日志与空目录 | **本轮新增“僵尸目录”入口** | 只处理有卸载记录且符合下述条件的路径；没有证据的目录保留 |
| 卸载后的配置、许可证、存档等 | 原“残留清理”会展示不同风险项 | 属于可能有价值的数据，与本轮只处理缓存和空目录的范围不同 |
| 失效注册表项、服务、任务和快捷方式 | 注册表清理已有实现 | 继续使用缺失目标依据、执行前核对和备份，不按注册项数量评估收益 |
| 重复文件与大文件 | 重复文件、空间分析已有实现 | 需要用户决定保留副本或用途；适合继续增加目录优先保留策略与空间增长追踪 |
| 隔离区中过期内容 | 隔离区已有实现 | 同卷移入隔离区一般不释放空间，到期或永久删除后才释放 |

下一步优先扩展“可确认的清理对象”，不增加“长时间未访问就删除”“文件夹名陌生就删除”等推断。

## 2. 本轮已实现

入口：左侧 **清理 → 僵尸目录**。

### 扫描依据

扫描使用新获取的安装清单和最近 1,000 条卸载记录。注册表清单不足现有可靠性阈值（5 条）时不生成候选。这个阈值是现有工程的保守检查，不保证所有安装来源都读取完整。

候选分为两类：

1. **已知缓存或日志**：卸载记录与应用名称归一化后精确匹配，当前没有匹配的已安装应用，指纹/规则的安装检测也未命中。路径必须来自指纹中的明确缓存子目录，或签名规则中 `safe + installed` 的缓存、日志目标。规则目标不含通配目录或前置动作，并保留原有文件模式、递归范围、最小年龄和文件名排除条件。
2. **真正为空的目录**：来自已确认应用指纹的目录，或卸载记录中精确的安装位置；目录必须连子目录都没有。文件数为零、子目录不可读或包含 Junction，都不能等同于空目录。

首版限定为当前用户的 Local、Roaming、LocalLow AppData。排除 Microsoft、Packages、Temp 等分支、Programs 根目录、OneDrive 路径、重解析点、云端占位目录以及路径护栏拒绝的目标。已安装应用的安装位置及能够检测到的运行程序路径也会阻止清理。

非空应用根目录不会整体移动。缓存按扫描时列出的文件逐个处理，因此同级设置、登录数据库和存档会保留；缓存根目录也会保留，搬空的内部子目录沿用现有引擎的非递归删除。空应用目录作为单独条目移入隔离区。

### 界面与执行

- 条目标记为“建议确认”，首次扫描默认不勾选；后续使用现有勾选记忆，并在执行时显示确认提示。
- 说明中展示应用、卸载记录日期和匹配的规则/指纹依据。
- 沿用筛选、白名单、隔离区、清理结果分类、重新扫描及 JSON 导出。
- 清理前重新扫描；重装、依据消失、规则范围缩小或白名单变化时，原条目跳过并保留。
- 无复核器或复核异常时不执行这些条目；取消时保留取消报告。
- 空目录在移动前再次直接枚举，防止新增的空子目录被文件指纹遗漏。文件仍执行大小、修改时间、真实路径及白名单检查。

### 明确的覆盖限制

- CleanSweep 以前没有记录的软件卸载，通常不会出现在本页。应用名不匹配、检测到遗留安装标志、规则未覆盖时，也可能漏报。
- 不处理 Program Files、ProgramData、其他用户目录、Documents、下载目录、聊天附件、游戏存档或任意磁盘上的未知文件夹。
- 不把缓存路径以外的 `config`、`data`、`User Data` 等非空目录作为垃圾；若用户主动把个人文件放进规则指定的缓存目录，程序无法从文件内容判断其用途，仍需核对路径后选择。
- 本轮复用现有验证通过的数据集，没有修改或重新签名规则。候选覆盖由当前规则和卸载记录决定，并非所有已卸载软件都能识别。
- 安装/运行状态检查与文件系统操作不是跨进程原子事务，不能保证清理过程中不存在其他程序同时改变状态。

## 3. 后续开发优先级

| 优先级 | 内容 | 完成标准 |
| --- | --- | --- |
| P1 | 扩大卸载缓存规则覆盖 | 为具体软件补充安装名称别名、可再生成目录和检测依据；每条规则有缓存与用户数据混放的反例测试，签名后才启用 |
| 首版已完成 | [卸载后在本页定向预览](卸载后定向预览-2026-10-02.md) | 复用卸载历史，按应用展示缓存和空目录，用户确认后执行；逐项保留原因展示仍待扩展 |
| P2 | 安装监控支持更准确的残留归属 | 利用已有快照记录，先提供变更预览；共享运行库、插件与其他程序引用的文件保持保留 |
| P2 | 项目构建输出识别 | 用户指定项目根目录，结合项目文件识别 bin/obj 等输出，避开源码、手工放置的数据和活动构建 |
| P2 | 空间变化追踪 | 同范围快照对比，优先定位新增或持续增长的目录，并标记权限不足与扫描不完整 |

表中标注“首版已完成”的定向预览已在后续一轮落地，其余仍为候选。后续综合计划见[开发计划](后续开发计划.md)。
