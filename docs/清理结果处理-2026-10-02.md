# 清理结果分类、重新扫描与导出

日期：2026-10-02。基于 v0.20.0 的未发布工作区改动；这是[开发计划](后续开发计划.md)第一项的首版。

## 使用方式

清理结束后，页面下方提供“上次清理结果与处理建议”：

- 分类查看已处理、正在使用、权限不足、扫描后变化、备份失败、安全排除、已不存在和未确认完成。
- 每条展示项目、路径、原因、下一步和可取得的错误码。
- “重新扫描未完成项”重新执行本页扫描，只展示原未完成项目的最新匹配结果；全部取消勾选，用户核对后再清理。
- “导出全部结果”保存 JSON，包含时间、程序版本、页面、批次、取消状态、条目结果、原因及建议。界面分类筛选不影响导出。

本地执行的失败、占用及跳过详情不再按原界面的 50 / 30 条截断。已完成动作按条目汇总计数，报告不包含每个成功移动文件的完整清单。导出保留本机路径，界面与保存窗口均提示分享前检查。

## 执行与兼容边界

- 备份、快照核对与路径护栏仍在执行链上。原因按异常类型、原生错误码或引擎分支提供，不从中文错误内容猜测。
- 注册表、服务和任务备份失败使用独立类别，备份失败不会继续删除对应目标。
- 取消清理通过兼容 OperationCanceledException 的异常携带已取得的结果；未确认完成的项目保留并取消选择。
- 上次结果保留到下一次清理产生新结果；普通扫描、重新扫描、取消和扫描失败都不清除它。当前报告保存在内存，关闭程序前可手动导出。
- 重新扫描没有再次检出项目，不等于此前已成功删除；白名单、规则变化、权限和软件状态都可能影响检出。
- 重新扫描仍运行本页扫描器，随后按原未完成条目 ID 限制展示范围；扫描速度不承诺随未完成数量减少。
- 提权服务新增可选原因类别，兼容旧结果。服务仍返回逐项摘要及每次请求最多 50 条文件失败明细，导出记录此限制；未知计数为 null。
- 服务取消或通信失败时，没有明确返回成功的条目保持“未确认完成”。本轮没有在真实 SYSTEM 服务环境重新验收。
- 自动脱敏诊断包、扫描性能优化及持久化结果历史留待后续。
